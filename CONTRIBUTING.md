# Contributing to RAGLite (Python)

Thanks for helping. Bug reports, docs fixes and pull requests are all welcome.

RAGLite has two SDKs that must behave the same: this Python package and the [TypeScript SDK](https://github.com/creatorpiyush/raglite). If your change affects chunking, tokenizing, scoring, citations or anything stored in an index, it needs a matching change in the other SDK (see [Cross-SDK fixtures](#cross-sdk-fixtures)). Open an issue first if you are unsure.

## Set up

Requires Python 3.11 or later.

```bash
git clone https://github.com/creatorpiyush/raglite-py.git
cd raglite-py
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
bash scripts/pre-commit.sh      # ruff, mypy and tests
```

## Make a change

1. Branch from `main` with a descriptive name, such as `fix/pdf-page-numbers` or `feat/pgvector-store`.
2. Add or update tests (`tests/unit`, `tests/integration`). Tests must not call real provider APIs; patch the embedders and `raglite.llm.answer._generate` as the existing tests do.
3. Run `bash scripts/pre-commit.sh` inside your virtual environment.
4. Add an entry under a dated version heading in `CHANGELOG.md`, and update the [documentation](#documentation) if users will notice the change.
5. Open a pull request and fill in the template.

### Dependencies

Provider SDKs are optional extras, imported on first use. A new provider or store should add an extra in `pyproject.toml` and import its package with `import_optional()` from `raglite/errors.py`, so users get a clear install message.

## Cross-SDK fixtures

`tests/fixtures/shared/*.json` are generated by the TypeScript SDK and pin the outputs both SDKs must produce. To change them, regenerate them in the TypeScript repo, then copy them here:

```bash
python scripts/sync_shared_fixtures.py --source ../raglite
```

CI fails if the copy here differs from the TypeScript SDK's.

## Documentation

The documentation site for both SDKs, https://creatorpiyush.github.io/raglite/, lives in the TypeScript repo under [`docs/`](https://github.com/creatorpiyush/raglite/tree/main/docs). Each code sample has a TypeScript and a Python tab: a user-visible change here needs a docs pull request there, in the same release. Every page has an "Edit page" link.

Keep `README.md` short: it is what PyPI shows, so it links to the site instead of repeating it.

## Live provider check

`python scripts/smoke_providers.py` calls each provider whose API key is set in your environment. It costs a few cents and is not part of CI; run it when you touch provider code or default models.

## Reporting bugs and security issues

Use the issue templates for bugs and feature requests. Report security problems privately as described in [SECURITY.md](SECURITY.md), not in a public issue.
